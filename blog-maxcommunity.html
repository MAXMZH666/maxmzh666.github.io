MAX社区开发历程：从零到上线

2026-10-10 · 标签：MAX社区 随笔

2026 年 10 月 2 日，MAX社区正式上线。从第一行代码到能注册、发作品、抢红包，前后只用了几天。这篇记录一下技术选型和踩过的坑。

技术选型：全部免费

原则就一条：不用钱。最后定的组合是：

  • GitHub Pages —— 静态托管，免费，部署就是 git push。
  • Supabase 免费版 —— 数据库 + 用户认证 + 文件存储，一套全包。
  • Cloudflare R2 + Worker —— 10GB 免费对象存储 + 无服务器函数，解决大文件上传和跨域问题。

纯前端 + BaaS 的架构，没有自己的服务器，半夜也不用担心运维。

核心功能是怎么长出来的

第一版只有作品发布和试玩，用的 TurboWarp 播放器直链。然后按"用户真正会用的顺序"往上加：

  1. 通知中心、关注、评论 —— 社区得有互动。
  2. 论坛、排行榜、收藏 —— 内容得有沉淀和发现。
  3. 在线编程（Scratch / Python / C++ / 网页）—— 降低创作门槛，浏览器里就能写。
  4. 积分商城、成长任务、邀请码、红包 —— 让用户愿意留下来。
  5. 工作室、赛事、私信、@提及 —— 从"作品站"变成"社区"。

踩过的几个坑

1. 魔法链接注册的 submit 拦截。从邮箱链接回来点"完成注册"毫无反应，查了半天发现是隐藏的必填输入框触发了浏览器原生表单校验，submit 事件根本没触发。教训：多步骤表单隐藏必填项时，一定要手动去掉 required。

2. 邀请码跨设备丢失。邀请码一开始只存 localStorage，用户在手机邮箱里点验证链接、回到电脑浏览器，码就没了。改成把邀请码拼在验证链接的 URL 参数里，问题解决。

3. R2 跨域静默失败。浏览器直传 R2 被 CORS 预检拦截，但代码里写了静默回退 Supabase，表面一切正常，实际大文件都在走慢通道。给桶加上 CORS 规则才真正用上 R2。

下一步

社区已经能用了，但内容还得靠大家。欢迎来 MAX社区 发第一个作品，或者去论坛 留个言。
